# 为什么关注纯血鸿蒙

### **系统方向**
- 纯血鸿蒙已经不是简单换皮系统；
- 应用运行环境、权限模型、包管理方式都有变化；
- Android 时代能用的方案，不一定可以直接搬过去；
- 想继续做工具、效率、生活、内容类应用，需要提前熟悉；

### **开发方向**
- 主语言：ArkTS；
- UI框架：ArkUI；
- 应用模型：Stage模型；
- 工程构建：DevEco Studio + Hvigor；
- 包名、签名、权限、调试、发布流程都需要重新熟悉；

### **用户方向**
- 后续新机型会逐步切换到 HarmonyOS NEXT；
- 用户会关心老功能还能不能用；
- 开发者需要提前判断哪些能力能适配；
- 能适配的先适配，不能适配的提前说明；

# 开发准备

### **开发环境**
- **DevEco Studio**
- 用于创建、运行、调试纯血鸿蒙工程；
- 建议保持官方推荐版本；
- 工程异常时，优先检查 SDK、Node、Hvigor 版本；

- **HarmonyOS SDK**
- 按目标系统版本安装对应 SDK；
- API 版本不同，能力和写法可能不一样；
- 示例代码不要只复制，要看目标 API 是否支持；

- **真机调试**
- 真机调试优先；
- 模拟器只能验证部分界面和基础逻辑；
- 权限、通知、文件、后台等能力，建议真机确认；

### **工程结构**
- **entry**：主模块，常用页面和业务逻辑放这里；
- **pages**：页面入口，按功能拆分；
- **components**：公共组件，按钮、卡片、弹窗等可复用；
- **model**：数据结构和状态对象；
- **utils**：日志、时间、格式化、权限工具类；
- **resources**：图片、颜色、字符串等资源；

# 手机端

### **基础页面**
- **首页**
- 展示核心入口；
- 不要一屏塞太多功能；
- 常用功能放前面，次要功能放设置里；

- **设置页**
- 放主题、权限、日志、版本信息；
- 配置项要能保存和恢复；
- 修改后给用户明确反馈；

- **关于页**
- 显示版本号、构建时间、公众号信息；
- 显示问题反馈入口；
- 显示必要的学习交流说明；

### **ArkUI 页面写法**
- 使用组件化方式拆页面；
- 大组件拆成小组件，后期维护更轻松；
- 状态变化尽量集中管理；
- 列表、弹窗、输入框先做通用封装；
- 深色、浅色主题提前考虑；

### **数据存储**
- 使用鸿蒙提供的数据存储能力；
- 用户配置、本地缓存、开关状态要分开管理；
- 本地配置建议带版本号，方便后期升级；
- 重要数据写入后要校验，避免用户升级后配置丢失；

### **权限说明**
- **通知权限**：用于显示状态和提醒；
- **网络权限**：用于接口请求和数据同步；
- **麦克风权限**：用于语音输入和语音指令；
- **文件权限**：用于图片选择、日志导出、导入导出等功能；
- **定位权限**：用于需要位置能力的功能；
- <span style="color:red">权限不要一次性全要，用到哪个再提示哪个；</span>

### **开发调试**
- 日志入口要保留；
- 崩溃信息要能复制；
- 接口错误要显示原因；
- 权限状态要能重新检测；
- 用户反馈时，尽量让用户一键复制基础信息；

# 设置面板

### **开发配置**
- **应用信息**
- 显示版本号、构建时间、系统版本；
- 用于用户反馈时快速定位问题；

- **调试开关**
- 开启后显示更多日志；
- 用于排查页面、接口、权限问题；
- 正式版本建议默认关闭；

- **能力检测**
- 检测当前系统版本；
- 检测权限授权状态；
- 检测设备是否支持相关能力；
- 检测失败时给出明确提示；

### **适配清单**
- **页面能力**
- 首页是否正常显示；
- 设置页是否正常保存；
- 弹窗、菜单、滑动列表是否正常；
- 深色、浅色主题是否正常；

- **系统能力**
- 通知是否可用；
- 网络请求是否稳定；
- 文件选择和保存是否可用；
- 后台任务是否符合系统限制；
- 分享、复制、跳转是否符合预期；

- **交互能力**
- 点击、长按、滑动是否正常；
- 输入框、键盘、焦点是否正常；
- 返回键和页面栈是否符合预期；
- 页面切换是否流畅；

# 开发路线

### **第一阶段：能跑起来**
- 创建纯血鸿蒙工程；
- 完成首页和设置页；
- 完成基础权限申请；
- 完成版本信息和日志入口；
- 先保证应用能安装、能启动、能退出；

### **第二阶段：能写页面**
- 完成通用按钮组件；
- 完成通用卡片组件；
- 完成弹窗和加载状态；
- 完成列表和空数据页面；
- 完成深色、浅色主题；

### **第三阶段：能保存配置**
- 完成主题、开关、用户配置；
- 完成本地数据读写；
- 完成配置升级兼容；
- 完成异常恢复处理；

### **第四阶段：能稳定使用**
- 完成错误提示；
- 完成日志复制；
- 完成权限重新检测；
- 完成用户反馈入口；
- 每一步都保留日志，方便后续排查；

# 注意事项

### **不要直接照搬 Android**
- Android 的 Activity、Service、Broadcast 等概念，不能按原样理解；
- 纯血鸿蒙有自己的应用模型和生命周期；
- 权限、后台、文件访问都要按鸿蒙规则来；
- 能力不明确的地方，先做验证 Demo；

### **不要一上来做大而全**
- 先做一个页面；
- 再做一个配置项；
- 再做一个权限申请；
- 再做一个接口请求；
- 小步快跑，比一次性重写更稳；

### **用户提示要清楚**
- 能用就显示可用；
- 不能用就说明原因；
- 需要权限就说明为什么；
- 需要新系统就说明最低版本；
- 不要让用户猜问题出在哪里；
